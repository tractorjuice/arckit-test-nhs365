# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

This is **not a software codebase**. It is an ArcKit enterprise-architecture governance workspace. There is no build, lint, or test toolchain and no application source; the sole executable is `scripts/pdf2md.py`, which regenerates the Markdown copy of the source book. The deliverables are versioned Markdown governance artifacts under `projects/`, generated by `/arckit:*` slash commands from the `arckit@arckit-claude` plugin (enabled in `.claude/settings.json`).

`/arckit:init` has run, so `projects/000-global/` exists with the source book in
`external/`. No `ARC-*.md` artifacts have been produced yet — `/arckit:navigator`
reports coverage and names the next command to run.

## Project goal

Produce a set of governance documents for **NHS 365**, derived from the source book:

- **Title:** *NHS 365 — A Best Practices Guide for Transforming UK Healthcare with Microsoft AI*
- **Publisher:** 365apps.pro, 23 pages, last modified 2026-08-11
- **URL:** `https://365apps.pro/wp-content/uploads/sites/50/2026/08/nhs365-book2.pdf`
- **Download note:** plain `curl` returns **403**; a browser `User-Agent` header is required.
- **In-repo:** `projects/000-global/external/nhs365-book2.pdf` (source of record) and
  `nhs365-book2.md` (converted, for ArcKit commands to read)

Chapters (use these as the scope boundary for artifacts):

1. Introduction — NHS England's Copilot rollout to 500,000+ staff, following the largest healthcare AI pilot to date
2. Strategic Architecture and Functional Deployment of Microsoft 365 within the NHS — licensing tiers (E-Frontline Worker, Enhanced Service), **shared vs sovereign tenant** decision factors, AI/automation risks
3. NHS Workforce Transformation: Microsoft 365 and Zensai for microlearning — workforce crisis, communities of practice, DSPT and Caldicott compliance
4. Best Practices for Microsoft Teams Rooms in Healthcare — MDT/tumour-board rooms, EHR integration, Purview retention (six years for clinical consultations), room design standards
5. Evolution of the NHS Care Identity Service Architecture — CIS2 authentication, national RBAC, smartcard lifecycle, OIDC Authorization Code flow, Registration Authorities, passkeys and biometrics

Domain implications: UK health and social care. The UK Government compliance commands apply — `/arckit:dpia`, `/arckit:secure`, `/arckit:tcop`, `/arckit:ai-playbook`, `/arckit:service-assessment`. The source also invokes NHS-specific regimes with no dedicated ArcKit doc type (DSPT, Caldicott principles, DCB0129/DCB0160 clinical safety, CQC); capture those inside `RISK` and `SECD` artifacts rather than inventing a new type code.

Use UK English spelling throughout — both the source document and the ArcKit templates do.

### Regenerating the source Markdown

The only executable in this repo. There is no build, lint, or test toolchain otherwise.

```bash
pip install pypdf
python3 scripts/pdf2md.py            # rewrites projects/000-global/external/nhs365-book2.md
```

Run it only after replacing the PDF with a newer edition. It exits non-zero and prints
counters if the conversion degrades — `unresolved_ligatures` and `orphan_fragments` must
both be `0`, and the 2026-08-11 edition yields 5 chapters, 29 subheadings, 153 paragraphs.

The PDF is a Designrr.io export with two traps the script handles, both documented in its
docstring: ligature glyphs carry no ToUnicode entry (pypdf emits NUL, so `staff` becomes
`sta`), and document structure is encoded purely in font size rather than markup. Callout
labels and two bold inline spans are drawn *after* the text they belong inside and are
reconstructed, not extracted — so **quote the PDF, not the Markdown, where exact wording
matters**. The generated front matter says the same.

## How work gets done

Everything runs through slash commands; do not hand-author `ARC-*.md` files. Hooks enforce naming and keep `docs/manifest.json` in sync, and a command's template carries the Document Control block that the staleness scanner and dashboard depend on.

- `/arckit:start` — orientation and workflow selection
- `/arckit:navigator` — coverage against the essential baseline; recommends the next command
- `/arckit:init` — scaffold `projects/`, `000-global/`, `.arckit/`
- `/arckit:build` — bulk-build artifacts in parallel waves with resumable state
- `/arckit:health` — stale research, forgotten ADRs, orphaned artifacts, version drift
- `/arckit:pages` — regenerate the governance dashboard

The `arckit:architecture-workflow` skill recommends a tailored command sequence when you are unsure of ordering.

Source material belongs in `external/` (project-scoped) or `projects/000-global/external/` (cross-project) before running commands — ArcKit commands scan those directories automatically for context. PDF, DOCX, MD, images, CSV, SRT/VTT and SQL are all supported.

## Artifact architecture

Filename convention, enforced by the `validate-arc-filename` PreToolUse hook (which auto-corrects rather than failing):

```
ARC-{PID}-{TYPE}[-{SEQ}]-v{VERSION}.md
```

- `{PID}` is the zero-padded project number and **must match the containing directory number** — `ARC-001-*` inside `projects/001-nhs365/`. A mismatch is silently rewritten to match the directory.
- `{SEQ}` (e.g. `ARC-001-ADR-003-v1.0.md`) appears **only** for multi-instance types: `ADR`, `DIAG`, `DFD`, `WARD`, `WGAM`, `WCLM`, `WVCH`, `DMC`, `RSCH`, `AWRS`, `AZRS`, `GCRS`, `DSCT`, `TNDR`, `CMPT`, `GOVR`, `GCSR`, `GLND`, `GRNT`, `CDAU`. Single-instance types omit it.
- `{TYPE}` must exist in the plugin's `config/doc-types.mjs` registry (167 codes across Discovery, Planning, Architecture, Compliance, Governance, Operations, Procurement, Reporting, Research). An unregistered code is a **fatal** write block, not a warning.

Directory layout:

```
projects/
├── 000-global/              # cross-project scope, PID 000
│   ├── ARC-000-PRIN-v1.0.md # architecture principles
│   ├── policies/            # org-wide governance policies
│   └── external/            # org-wide reference documents
└── 001-nhs365/              # per-project scope, PID 001
    ├── ARC-001-REQ-v1.0.md  # top-level artifacts sit at project root
    ├── decisions/           # ADR
    ├── diagrams/            # DIAG, DFD
    ├── wardley-maps/        # WARD, WDOC, WGAM, WCLM, WVCH
    ├── research/            # RSCH, DSCT, TNDR, CMPT, GOVR, GRNT, AWRS/AZRS/GCRS…
    ├── audits/              # CDAU
    ├── data-contracts/      # DMC
    ├── framework/           # FWRK
    └── external/            # project reference documents (put the NHS 365 PDF here)
```

Subdirectory placement is not stylistic — it is fixed by `SUBDIR_MAP` in the plugin's doc-type registry and enforced on write.

Generated state, not hand-edited:

- `docs/manifest.json` — artifact index, updated incrementally after every `ARC-*.md` write
- `.arckit/` — plugin state: `config.json`, `state.json`, `memory/` (session and principles context), `templates/` (per-project template overrides via `/arckit:customize`)

## Regime and severity tags

Doc types carry an optional `regime` tag (`UK`, `MOD`, `EU`, `US`, …) and a `severity` tag. `HIGH`-severity types drive the Compliance Readiness scorecard in `/arckit:graph-report`, scored **per regime** — so a UK-scoped project is not penalised for missing MOD or EU artifacts. Universal types (`RISK`, `SECD`, `TRAC`, `CONF`, `PRIN-COMP`) deliberately carry no regime.

Adding or renaming a type code requires dual registration: `config/doc-types.mjs` **and** the allow-list inside `commands/pages.md`. Without both, artifacts are recorded in the manifest but silently omitted from the dashboard sidebar.

## MCP servers

AWS Knowledge and Microsoft Learn work with no configuration — relevant here, since the source document is Microsoft 365 and Azure AI centred, so `/arckit:azure-research` is directly applicable. Google Developer Knowledge (`GOOGLE_API_KEY`) and Data Commons (`DATA_COMMONS_API_KEY`) require keys; without them those two servers error in the plugin UI while every other command continues to work.
