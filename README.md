# arckit-test-project-v53-nhs365

An [ArcKit](https://github.com/tractorjuice/arckit-claude) enterprise-architecture
governance workspace for **NHS 365** — the adoption of Microsoft 365, Copilot, and
related AI capabilities across NHS organisations.

This is not a software codebase. The deliverables are versioned Markdown governance
artifacts under `projects/`, generated by `/arckit:*` slash commands.

## Source document

All artifacts derive from:

> **NHS 365 — A Best Practices Guide for Transforming UK Healthcare with Microsoft AI**
> 365apps.pro · 23 pages · published 2026-08-11
> [`nhs365-book2.pdf`](projects/000-global/external/nhs365-book2.pdf)

The book covers NHS England's Copilot rollout to 500,000+ staff, Microsoft 365 strategic
architecture (shared vs sovereign tenancy), workforce transformation and microlearning,
Teams Rooms in healthcare, and the NHS Care Identity Service (CIS2).

A converted Markdown copy sits alongside the PDF for machine reading. Where exact
wording matters, quote the PDF — see [Converting the source book](#converting-the-source-book).

**ARC-000-PRIN** — 21 technology-agnostic principles across Strategic, Data, Clinical,
Integration, Quality, and DevOps categories. Two are non-waivable: Security by Design
and Clinical Safety by Design. The Clinical category (principles 10–12) covers clinical
safety under DCB0129/DCB0160, human accountability for AI output, and identity assurance.

**ARC-001-STKE** — 30 stakeholders, 16 drivers, 8 goals, 6 outcomes, and 7 stakeholder
risks, with full Stakeholder → Driver → Goal → Outcome traceability. Documents five
conflicts, the sharpest being delivery pace against the clinical safety gate.

Artifacts are named `ARC-{PID}-{TYPE}[-{SEQ}]-v{VERSION}.md`, where `{PID}` must match

## Working in this repository

Artifacts are generated by slash commands, not hand-authored — the templates carry the
Document Control block that the staleness scanner and dashboard depend on.

```text
/arckit:navigator      # coverage against the baseline; recommends the next command
/arckit:requirements   # next step — requirements aligned to the stakeholder goals
/arckit:risk           # risk register (Orange Book)
/arckit:dpia           # Data Protection Impact Assessment
/arckit:pages          # generate the governance dashboard
```

Reference documents belong in `external/` before running commands — ArcKit scans those
directories automatically for context.

## Converting the source book

The only executable here. Re-run it only after replacing the PDF with a newer edition.

```bash
pip install pypdf
python3 scripts/pdf2md.py
```

The PDF is a Designrr.io export with two traps the script handles: ligature glyphs carry
no ToUnicode entry (so `staff` extracts as `sta`), and document structure is encoded in
font size rather than markup. Callout labels and two bold inline spans are drawn *after*
the text they belong inside and are reconstructed rather than extracted.

The script exits non-zero if the conversion degrades — `unresolved_ligatures` and
`orphan_fragments` must both be `0`. The 2026-08-11 edition yields 5 chapters,
29 subheadings, and 153 paragraphs.

## Compliance context

UK health and social care. Artifacts are classified `OFFICIAL` and use UK English.
Beyond the UK Government regimes ArcKit covers directly (`/arckit:dpia`, `/arckit:secure`,
`/arckit:tcop`, `/arckit:ai-playbook`, `/arckit:service-assessment`), the source invokes
NHS-specific regimes with no dedicated ArcKit doc type — DSPT, Caldicott principles,
DCB0129/DCB0160 clinical safety, and CQC. Those are captured inside `RISK` and `SECD`
artifacts rather than as new type codes.
